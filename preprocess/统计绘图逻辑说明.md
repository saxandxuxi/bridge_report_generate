# 桥数据预处理 · 统计与绘图逻辑说明

> 本文用通俗的语言说明：数据是怎么从"秒级原始记录"一步步变成"小时统计、
> 季度统计、统计图和中文对照表"的；极端值是怎么判定的；以及传感器编号
> 是怎么和中文名称对应起来的。适合不了解代码的人阅读。

---

## 1. 整体流程一览

```
秒级原始 CSV（每传感器/每特征/每小时一个文件）
        │  ① 预处理：一个文件 = 一个小时，聚合出小时统计
        ▼
daily/<传感器>/<特征>/<日期>.csv   （每天最多 24 行小时统计）
        │  ② 进一步清洗 + 统计 + 绘图
        ▼
统计值/<传感器编号>.json        每个传感器的分特征统计
统计值_<期>/<桥名>/季度总结/季度统计.json
                              按监测部位合并多传感器的季度统计
统计值_<期>/<桥名>/季度总结/年度统计.json
                              按监测部位合并多传感器的年度统计
图库/<传感器编号>/<特征>/*.png  时间序列图 / 频率分布图 / 相关性图
传感器对照/传感器编号名称.json       编号 → 中文名称（固定产物）
传感器对照/传感器名称对照/<桥名>.json 中文名称 → 编号 / 特征 / 位置 / 方向（固定产物）
```

对应脚本（都在 `处理脚本/` 文件夹）：

| 脚本 | 作用 |
| --- | --- |
| `preprocess_sensor_data.py` | ① 秒级 → 小时级（原始数据预处理） |
| `build_chart_library.py` | ② 清洗 + 统计值 + 图库 |
| `build_quarterly_stats.py` | ② 季度统计（小时级、按部位合并） |
| `parse_sensor_map.py` | ③ 从测点编号表格生成中文对照 |

## 2. 从秒级到小时级（预处理）

### 2.1 原始数据长什么样

原始文件按"一个传感器、一个特征、一个小时"存放，例如：

```
D:\信科采集软件解析数据\103\2026\03\03\103_2026030300_WSD(rh).csv
```

文件名拆开看：

| 部分 | 含义 |
| --- | --- |
| `103` | 传感器编号 |
| `2026030300` | 2026年03月03日 00 时 |
| `WSD(rh)` | 模块(特征)：WSD 模块的湿度 |

文件内容类似（没有表头）：

```
0000000,55.8438
0000100,55.4688
0000200,55.4688
...
```

- 第一列：**计数器**，表示这一行数据相对文件起始的时间（毫秒，程序会自动按
  "一个文件 = 1 小时"校正单位）；
- 第二列：**测量值**。

### 2.2 怎么变成小时统计

一个文件正好是一个小时，所以预处理时把文件里所有行汇总成这一小时的统计：

- **count**：这一小时有多少个有效数据点
- **mean**：平均值
- **min / max**：最小 / 最大值
- **sum**：总和
- **std**：标准差
- **median**：中位数

一天有 24 个文件，就得到 24 行，写进
`daily/<传感器>/<特征>/<日期>.csv`，例如：

```
bucket_start,count,mean,min,max,sum,std,median
2026-03-03T00:00:00,3600,55.2,54.1,56.3,198720,0.6,55.2
2026-03-03T01:00:00,3600,55.5,54.3,56.8,199800,0.7,55.5
...
```

所以 **daily 文件是最小单位"小时"的统计结果**，之后的统计和绘图都从这里出发。

> 补充：原始数据如果中途中断或续跑，程序会断点续跑，并且汇总表
> `summary.csv` 会在最后按"传感器/特征/日期"排序去重，不会因为多跑几次而重复。

## 3. 统计逻辑

### 3.1 先清洗，再统计

统计之前，所有数据都要先过一遍"清洗"，**统计用的数据和画图用的数据是同一套清洗
后的数据**，不会出现图上一个样、统计另一个样。

清洗分三步：

1. **物理范围过滤**（见第 4 节）——把明显不可能的值（如湿度 435000%）直接剔除；
2. **零散尖峰替代**（见第 4 节）——把突然窜高/窜低的单个点用稳健基线替代；
3. **突变段检测**（只标注，不修改数据）——长时间整体偏高/偏低只在图上画出来。

### 3.2 每个传感器每个特征算什么

以 `daily` 的小时数据为基础，算以下统计值（中文键，方便查询）：

| 统计值 | 含义 |
| --- | --- |
| 平均值 | 所有有效小时均值的平均值 |
| 最大值 / 最小值 | 小时均值的最大 / 最小 |
| 差值 | 最大值 - 最小值 |
| 最大值_实测 / 最小值_实测 | 所有小时最大值的最大 / 所有小时最小值的最小 |
| 绝对最大值 | \|最大值_实测\| 和 \|最小值_实测\| 里更大的那个 |
| 均方根值 | 小时均值的均方根（反映整体能量水平） |
| 标准差 | 小时均值的波动程度 |
| 中位数 | 小时均值的中位数 |
| 有效小时数 / 缺失小时数 | 有数据 / 没数据的小时数 |
| 覆盖天数 | 有数据的天数 |
| 每日统计 | 每天的 平均值/最大值/最小值 明细 |

结果写在 `统计值/<传感器编号>.json`，一个传感器一个文件。

### 3.3 季度统计（按监测部位合并）

很多监测部位不止一个传感器，比如"第五跨L/4处主梁"上有 178、295、297、298、
301、302 六个温度传感器。单独看某一个会以偏概全，所以季度统计按**监测部位**合并：

- 每个传感器先各自清洗；
- 同一部位同一特征：**按小时取各传感器的平均值**（这一个小时该部位的代表值）；
- 最大值取各传感器的最大，最小值取各传感器的最小；
- 再用合并后的小时序列计算季度统计值。

结果写在 `统计值_<期>/<桥名>/季度总结/季度统计.json`
(年度为 `季度总结/年度统计.json`)，结构是：
`桥名 → 监测部位 → 特征 → {统计值, 参与传感器列表, 剔除异常值数}`。

> 例：178（均值约10℃）和 295（均值约12℃）合并后，该部位季度平均温度 ≈ 11℃。

## 4. 极端值怎么判定

这是最容易出问题的地方，也是之前出现"75958600℃""435000%"的根源——原始数据里
混入了采集设备的错误码，必须先用两道关卡挡掉，再算统计。

### 4.1 第一道：物理合理范围

按特征类型规定一个"人眼一看就不可能"的范围，超出的值一律用稳健基线替代：

| 特征 | 合理范围 | 说明 |
| --- | --- | --- |
| 湿度 `rh` | 0 ~ 100 % | 湿度不可能超过 100% |
| 温度 `temp` | -80 ~ 80 ℃ | 桥面温度的正常范围 |
| 风速 `spfs`/`szfs` | 0 ~ 100 m/s | 最大台风也就这个量级 |
| 风向 `spfx`/`szfx` | 0 ~ 360° | 角度范围 |
| 应变 `rsg` | -5万 ~ 5万 με | 结构应变量级 |
| 加速度 `xJsd` | -1万 ~ 1万 mg | 加速度量级 |
| 倾角 `xJd`/`yJd` | -90° ~ 90° | 角度范围 |
| 挠度 `nd` | -10万 ~ 10万 mm | 挠度量级 |
| 索力 `sl` | 0 ~ 10万 KN | 索力不可能为负 |
| 裂缝 `lf` | -1万 ~ 1万 mm | 裂缝宽度量级 |
| 位移/空间变位 `Δx/Δy/Δz` | -10万 ~ 10万 mm | 位移量级 |

像 435000、90005000、-5959240 这类值在这里就被直接拦下。

### 4.2 第二道：零散尖峰判定

有些值虽然在物理范围内，但和周围数据比明显异常。比如某个特征长期在
[-1, 1] 之间浮动，突然某个小时变成 100——平均值就会被这一个点带偏。

判定规则：

1. **稳健基线**：先把数据里上、下各 5% 的极端值去掉，再取中位数作为"正常水平"
   （这样基线不会被那一个 100 拉偏）；
2. **稳健尺度（MAD）**：衡量数据正常波动的大小；
3. 某个点如果偏离稳健基线超过 **5 倍** 波动尺度，并且**连续不超过 3 个小时**，
   就判定为"零散尖峰"；
4. **数量上限**：每个序列（均值/最大/最小）最多替代 `--max-spikes`（默认 3）
   个**最极端**的尖峰，其余较高的值视为"正常分布尾部"（比如风速数据里
   平时 1~2 m/s、偶尔刮风 5~9 m/s，这些刮风天不算尖峰）；
5. **规律性高峰保护**：如果同一个小时（比如每天 7~8 点、17~18 点）在多个日期
   都出现高值，说明这是"早晚高峰"之类的常态规律，**不算尖峰**，不替代；
6. **风类特征不做统计尖峰替代**：
   - 风向（`spfx`、`szfx`）是圆形量，0° 和 360° 是同一个方向，线性
     "偏离多少倍"没有意义；
   - 风速（`spfs`、`szfs`）是长尾分布——平时 1~2 m/s，刮风天 5~30 m/s、
     阵风可达 45 m/s，这些都是**真实天气**，不是尖峰，不能用统计方法替代；
   - 所以风类特征只做物理范围过滤（删 5000 m/s 这种不可能值），
     不做 MAD 尖峰替代。

> 例：人流量数据早高峰 8 点就是高，不能把每天 8 点的值都当尖峰删掉。

> 图上的标记：**黑色 × = 统计尖峰（最多每序列 3 个）**，
> **红色 × = 物理范围外的值（如 5000 m/s 这种不可能值，一律剔除）**。

### 4.3 长时段数据缺失

如果相邻两个有效小时之间间隔 **≥ 24 小时**（比如整整一天没数据）：

- 在图上用橙色标注缺失区间，并注明"数据缺失 N 小时，已线性填充"；
- **绘图时**用缺失区间前后两个有效值做线性插值，让曲线连续；
- **统计时不使用填充值**——填充只是为了看图，统计值仍然只算真实数据。

## 5. 绘图逻辑

### 5.1 时间序列图

- 横轴是日期，但**一天画 24 个点**（小时级），所以三个月就是 24×30×3 个点，
  曲线能看出一天内的变化；
- 三条线：小时均值（主曲线）、小时最大值、小时最小值；
- 标题：`监测部位名称（编号XX）- 特征 时间序列`，图例上也带编号，
  这样同一部位多个传感器（如 178 和 295）的图不会混；
- 被替代的尖峰点用黑色 × 标出来；
- 突变区间用红色/绿色着色，并标注"x月x日x时 ~ x月x日x时 均值xx 偏高/偏低"；
- 数据缺失 ≥24h 用橙色着色并标注。

### 5.2 突变区间（长时间偏高/偏低）怎么判定

1. 每个小时先和稳健基线比，打"高 / 低 / 正常"标签；
2. 统计**一天里偏高小时占比**：只有占比 ≥ 60% 的天才算"突变天"；
3. 连续 **≥ 7 天**的突变天合并成一个突变区间；
4. 起止时间精确到小时，标注在图上，同时写进统计 JSON 的"突变区间"。

这样设计是为了避免把正常的日常波动、或只有几天的抖动误判成突变。

### 5.3 频率分布图

把所有有效小时均值画成直方图，看数值集中在哪个区间、分布是否正常。

### 5.4 相关性图（可选 `--correlation`）

同一传感器不同特征之间（比如温度和应变）按日期对齐，画密度散点图 +
回归直线，并给出相关系数 r 和回归方程。

## 6. 传感器与编号映射

### 6.1 数据来源

所有映射都来自《五座桥测点编号表格.docx》，按"桥名 → 监测类别 → 表格"组织。
例如：

```
赤石大桥 → 结构温度 → 第五跨L/4处主梁 → 178、295、297、298、301、302
```

### 6.2 解析出了哪些信息

对每一行表格：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| 编号 | 传感器编号 | 100 |
| 桥名 | 属于哪座桥 | 赤石大桥 |
| 类别 | 监测类别 | 温湿度 / 结构温度 / 应变 / 振动 ... |
| 位置 | 上游/下游/左幅/右幅 | 上游 |
| 方向 | X/Y/Z 等 | X |
| 监测部位 | 中文位置名称 | 5#塔左塔锚固区 |

### 6.3 输出两个方向的对照

1. **编号 → 名称**：`传感器对照/传感器编号名称.json`（固定产物，不随季度变化）
   ```json
   "100": {"桥名": "赤石大桥", "类别": "温湿度", "位置": "上游",
           "监测部位": "5#塔左塔锚固区", "特征编码": ["WSD(rh)", "WSD(temp)"]}
   ```
2. **名称 → 编号**：`传感器对照/传感器名称对照/<桥名>.json`（五座桥各一个文件，固定产物）
   ```json
   "5#塔左塔锚固区": [{"编号": "100", "特征": "温湿度",
                       "位置": "上游", "特征编码": ["WSD(rh)", "WSD(temp)"]}]
   ```

### 6.4 几个关键约定

- **一个名称可能对应多个编号**：比如"第五跨L/4处主梁"有 6 个温度传感器，
  所以名称后面的值是一个列表；
- **特征编码**：从 Q1 统计值里自动读到的实际特征名（如 `WD(temp)`、
  `YB(rsg)`、`DZJSD(xJsd)`），用于和统计 JSON 对得上；
- **测点**：应变/振动监测表里"测点1~测点6"按测点编号表的出现顺序编号；
- **倾角 X/Y**：同一个传感器同时测 X、Y 两个方向，X 用 `EZJD(xJd)`，
  Y 用 `EZJD(yJd)`；
- **空间变位表里的"平均值（mm）"列**：那列数字其实是传感器编号，解析时
  已按编号处理，不会当成数值。

## 7. 常用参数速查

运行 `python 处理脚本\build_chart_library.py --help` 可以看到全部参数，常用的：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--spike-threshold` | 5.0 | 尖峰判定阈值（偏离稳健基线多少倍波动），调大更宽松 |
| `--gap-fill-hours` | 24 | 缺失达到多少小时才填充，0 = 关闭 |
| `--shift-threshold` | 2.5 | 突变段判定阈值 |
| `--shift-min-days` | 7 | 突变段最短持续天数 |
| `--correlation` | 关 | 是否生成相关性图 |
| `--limit-sensors` | 0 | 只处理前 N 个传感器（试跑用） |
| `--start / --end` | 全部 | 只统计指定日期范围 |

流量/计数类特征（如人流量）如果不想做尖峰处理，可以加 `--spike-threshold 0`。

## 8. 常见问题

**Q1：统计值里还能看到离谱的数？**
说明这个值不在物理范围表里（可能是新的错误码），把范围加进
`build_chart_library.py` 的 `FEATURE_RANGES` 再重新跑即可。

**Q2：图上曲线和统计值对不上？**
一般是长时段缺失的线性填充造成的——填充值只用于绘图，统计值不含填充值。

**Q3：尖峰删太多了 / 太少了？**
调 `--spike-threshold`：值调大 = 更宽松（少删），调小 = 更严格（多删）。

**Q4：为什么同一部位多个传感器要取均值？**
因为一个监测部位（比如一段梁）放了多个测点，取均值代表"这个部位的整体水平"，
单独一个传感器可能受局部影响。
